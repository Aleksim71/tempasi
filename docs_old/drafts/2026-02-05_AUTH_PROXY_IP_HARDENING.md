# Tempasi — Auth: Proxy / Client IP Hardening

Дата: 2026-02-05
Статус: draft
Область: Auth / Security / Rate-limit

---

## Контекст

В auth используется rate-limit логина для защиты от brute-force атак.
Ключ лимита включает IP клиента.

Проблема: заголовок `X-Forwarded-For` (**XFF**) может быть подделан клиентом,
если сервер не находится за доверенным reverse-proxy.

---

## Цель

Гарантировать, что IP, используемый для rate-limit:

- нельзя подменить напрямую с клиента
- корректно определяется за reverse-proxy (nginx)
- управляется конфигурацией, а не «магией»

---

## Подход (MVP)

Используется **явная модель доверия**:

1. По умолчанию:
   - `X-Forwarded-For` **игнорируется**
   - используется прямой IP соединения (`req.ip`)

2. Если включён `TRUST_PROXY=1`:
   - `X-Forwarded-For` **может** использоваться

3. Если задан allowlist прокси:
   - `XFF` принимается **только если**
     прямой peer-IP входит в список доверенных прокси

---

## Реализация

### ENV-переменные

```env
TRUST_PROXY=1
TRUST_PROXY_IPS=127.0.0.1,::1
```
